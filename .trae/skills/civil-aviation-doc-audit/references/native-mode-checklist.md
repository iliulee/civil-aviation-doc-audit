# 原生模式审核检查清单（v8.1 新增）

> 本文件供**原生模式**下 AI 逐条对照执行。每条检查项提供明确的"是/否"判断标准和规范依据，不依赖 Python 规则引擎。低智商模型按本清单机械执行即可完成审核。

> **使用方式**：AI 在原生阶段 3 开始时，读取本文件，逐条对照数据底座中的 JSON 数据进行检查。每条检查项输出：✅ 通过 / ❌ 不通过（附问题描述+规范条款+整改建议）。

---

## 一、OCR 数据质量检查（铁律 10，前置硬门槛）

> **执行顺序**：本节必须在规范对账之前完成。发现 error 级问题 → 停止后续审核，要求重新提取。

### DQ-1 重复值检测
- **检查什么**：同一份文档中，是否有仅 2 个值交替出现的情况
- **怎么查**：统计每列的不重复值数量，如果某列只有 2 个值且交替出现 → 造假嫌疑
- **判断标准**：不重复值 ≤ 2 且交替出现 → ❌ 数据造假嫌疑
- **规范依据**：铁律 10 / DQ-REPEAT

### DQ-2 突变检测
- **检查什么**：桩长、灌入量、高程等关键参数是否有断崖式下跌
- **怎么查**：计算相邻行的参数变化率，|变化率| ≥ 30% → 标记
- **判断标准**：变化率 ≥ 30% 且无说明 → ❌ 需说明原因
- **规范依据**：铁律 10 / DQ-JUMP

### DQ-3 涂改痕迹检测
- **检查什么**：充盈系数是否自洽、桩长是否等于桩顶高程-桩底高程
- **怎么查**：逐行验证 数学关系是否成立
- **判断标准**：数学关系不成立 → ❌ 数据被修改嫌疑
- **规范依据**：铁律 10 / DQ-ALTER

### DQ-4 数据自洽检测
- **检查什么**：行数是否合理、桩号是否连续、工程计算是否自洽
- **怎么查**：
  - 桩号连续性：Z401 → Z402 → Z403...，缺号 → 标记
  - 行数合理性：施工记录行数 ≈ 桩数 × 每桩记录次数
  - 合计行：有合计值的文档，合计 = 各行之和
- **判断标准**：桩号跳号、合计不符 → ❌ 数据不完整
- **规范依据**：铁律 10 / DQ-SELF

## 二、铁律检查（L1，15 个核心检查项）

### IR-1 规范可追溯性
- **检查什么**：每条审核意见是否引用了具体规范编号和条款号
- **怎么查**：AI 自检输出的每条意见，是否包含"MH/T XXXX 第 X 条"格式引用
- **判断标准**：缺少规范引用 → ❌ 违反铁律 1
- **规范依据**：铁律 1

### IR-2 OCR 人工复核标记
- **检查什么**：扫描件 OCR 数据是否经过人工核对（human_verified = true）
- **怎么查**：检查 index.json 中所有文档的 human_verified 字段
- **判断标准**：存在 human_verified = false → ❌ 违反铁律 2，停止审核
- **规范依据**：铁律 2

### IR-3 运算审核规范性
- **检查什么**：运算审核是否只做规范性检查（不做数值复算）
- **怎么查**：AI 自检是否对施工资料中的计算结果做了数值复算
- **判断标准**：做了数值复算 → ❌ 违反铁律 3
- **规范依据**：铁律 3

### IR-4 审核结论明确性
- **检查什么**：每条不符合项是否包含：问题描述 + 违反条款 + 整改建议
- **怎么查**：AI 自检每条意见的三个字段是否齐全
- **判断标准**：缺少任一字段 → ❌ 违反铁律 4
- **规范依据**：铁律 4

### IR-5 资料归档标准
- **检查什么**：资料是否按 MH/T 5078.1-2024 要求分类组卷编目
- **怎么查**：检查资料分类是否正确、编目是否规范
- **判断标准**：分类错误或编目不规范 → ❌ 违反铁律 5
- **规范依据**：铁律 5 / MH/T 5078.1-2024

### IR-6 伪造资料检查
- **检查什么**：是否存在时间倒签、代签字、数据雷同等伪造嫌疑
- **怎么查**：
  - 时间倒签：施工日期晚于验收日期
  - 代签字：同一人签字笔迹明显不同
  - 数据雷同：不同桩号的数据完全相同
- **判断标准**：存在伪造嫌疑 → ❌ 违反铁律 6，必须明确指出
- **规范依据**：铁律 6

### IR-7 审核留痕
- **检查什么**：审核日志是否包含：审核时间、依据规范版本、OCR 置信度、人工复核标记、审核结论
- **怎么查**：检查审核日志 JSON 是否包含上述字段
- **判断标准**：缺少任一字段 → ❌ 违反铁律 7
- **规范依据**：铁律 7

### IR-8 未发现问题表述
- **检查什么**：未发现不符合项时，是否明确写出"未发现不符合项"
- **怎么查**：AI 自检审核结论，是否使用了"全部合格"等简化表述
- **判断标准**：使用"全部合格" → ❌ 违反铁律 8
- **规范依据**：铁律 8

### IR-9 资料阶段判定
- **检查什么**：过程资料是否按归档标准判定签字完整性
- **怎么查**：检查前置信息中的"阶段"字段，过程资料签字判定标准是否降级
- **判断标准**：过程资料按归档标准判定 → ❌ 违反铁律（过程资料上下文）
- **规范依据**：项目记忆 — 过程资料不按归档标准判定

### IR-10 排除文件声明
- **检查什么**：排除文件是否在审核前明确声明
- **怎么查**：检查前置信息中的 excluded_files 字段
- **判断标准**：存在未声明的排除文件 → ❌ 违反铁律
- **规范依据**：项目记忆 — 排除文件需在审核前明确声明

### IR-11 OCR 存疑项处理
- **检查什么**：OCR 存疑项是否汇总为"待核实清单"
- **怎么查**：检查审核报告中是否包含 OCR 待核实清单
- **判断标准**：OCR 存疑项未汇总 → ❌ 违反铁律 20
- **规范依据**：铁律 20

### IR-12 手写潦草标注
- **检查什么**：手写潦草内容是否特别标注（如施工日期年份可能被误读）
- **怎么查**：检查 OCR 识别结果中手写内容的标注
- **判断标准**：手写潦草内容未标注 → ❌ 违反铁律
- **规范依据**：项目记忆 — 手写潦草内容识别需特别标注

### IR-13 依据文件归类
- **检查什么**：设计变更文件是否自动归类为依据文件
- **怎么查**：检查文件分类中设计变更文件的归类
- **判断标准**：设计变更文件归为被审核资料 → ❌ 违反铁律
- **规范依据**：项目记忆 — 设计变更文件自动归类为依据文件

### IR-14 施工日志降级
- **检查什么**：同时存在施工日志和施工记录/检验批时，施工日志是否降级为依据文件
- **怎么查**：检查文件分类中施工日志的归类
- **判断标准**：施工日志未降级 → ❌ 违反铁律
- **规范依据**：项目记忆 — 施工日志自动降级为依据文件

### IR-15 审核报告完整性
- **检查什么**：HTML 审核报告是否包含 9 章节强制结构
- **怎么查**：检查报告是否包含：项目基本信息 / 审核范围 / 审核依据 / 审核结果汇总 / 分部分项审核详情 / 逻辑一致性检查 / 签字异常专区 / 整改建议清单 / 审核日志
- **判断标准**：缺少任一章节 → ❌ 违反铁律 18/19
- **规范依据**：铁律 18/19

## 三、逻辑一致性检查（L2，铁律 9 的 10 个子项）

### LG-1 时间轴一致性
- **检查什么**：同一事件的日期在不同文档中是否一致
- **怎么查**：
  - 施工日期 ≤ 验收日期 ≤ 报审日期
  - 监理日志日期 ≥ 对应施工记录日期（监理见证在后）
  - 开工日期 ≤ 所有施工日期 ≤ 竣工日期
- **判断标准**：日期逻辑矛盾 → ❌ Sanity Check
- **规范依据**：铁律 9.1

### LG-2 数量累计一致性
- **检查什么**：分项工程量之和 = 分部工程量 = 单位工程量
- **怎么查**：逐级汇总，检查加法是否成立
- **判断标准**：汇总不符 → ❌ Sanity Check
- **规范依据**：铁律 9.2

### LG-3 人员交叉一致性
- **检查什么**：同一人在不同文档中的角色是否一致
- **怎么查**：提取所有文档中的签字人姓名和角色，交叉比对
- **判断标准**：同一人角色矛盾 → ❌ Sanity Check
- **规范依据**：铁律 9.3

### LG-4 状态描述一致性
- **检查什么**：同一施工部位的状态在不同文档中是否一致
- **怎么查**：如施工记录写"合格"但验收记录写"不合格" → 矛盾
- **判断标准**：状态矛盾 → ❌ Sanity Check
- **规范依据**：铁律 9.4

### LG-5 签字一致性
- **检查什么**：同一人在不同文档上的签字是否一致
- **怎么查**：原生模式下 AI 视觉对比签字图像（如有）
- **判断标准**：签字明显不同 → ❌ 代签嫌疑
- **规范依据**：铁律 9.5

### LG-6 因果逻辑一致性
- **检查什么**：施工记录描述的因果关系是否合理
- **怎么查**：如"因下雨停工"但气象记录显示当天晴 → 矛盾
- **判断标准**：因果矛盾 → ❌ Sanity Check
- **规范依据**：铁律 9.6

### LG-7 规范引用一致性
- **检查什么**：不同文档引用的规范编号是否一致
- **怎么查**：如施工方案引用 MH 5007-2010 但验收记录引用 MH 5007-2023 → 版本不一致
- **判断标准**：规范版本不一致 → ❌ Sanity Check
- **规范依据**：铁律 9.7

### LG-8 试验检测逻辑一致性
- **检查什么**：试验报告的检测日期、检测方法、检测结果是否与施工记录匹配
- **怎么查**：试验日期 ≥ 施工日期（先施工后检测），检测方法符合规范要求
- **判断标准**：逻辑矛盾 → ❌ Sanity Check
- **规范依据**：铁律 9.8

### LG-9 跨资料合计值反向验证
- **检查什么**：施工日志的合计值 = 各施工记录的累计值
- **怎么查**：施工日志有合计值时，逐项核对与施工记录的累计值
- **判断标准**：合计值不符 → ❌ 标记"来源不明"
- **规范依据**：铁律 9.9

### LG-10 监理-施工方跨单位日期对照
- **检查什么**：监理方资料与施工方资料的日期逻辑关系
- **怎么查**：
  - 监理旁站记录日期 ≥ 对应施工记录日期
  - 监理通知单日期 ≤ 施工方回复单日期
  - 工程暂停令日期 ≤ 复工令日期
  - 报审表日期 ≤ 监理审批日期
- **判断标准**：日期对不上 → ❌ 流程倒签或资料造假
- **规范依据**：铁律 9.10

## 四、业务合理性检查（L3）

### BG-1 桩长突变率
- **检查什么**：相邻桩的桩长变化是否合理
- **怎么查**：|桩长_i - 桩长_{i-1}| / 桩长_{i-1} ≥ 30% → 警告
- **判断标准**：突变率 ≥ 30% → 🔵 Best Practice 警告
- **规范依据**：L3 业务合理性

### BG-2 充盈系数范围
- **检查什么**：充盈系数是否在合理范围内
- **怎么查**：充盈系数 = 实际灌入量 / 理论灌入量，合理范围 0.9~1.3
- **判断标准**：超出范围 → 🔵 Best Practice 警告
- **规范依据**：L3 业务合理性

### BG-3 签字完整性
- **检查什么**：各栏目签字是否齐全
- **怎么查**：施工方/监理方/建设单位签字栏是否均有签字
- **判断标准**：缺签 → 按资料阶段判定（过程资料降级，归档资料严格）
- **规范依据**：L3 业务合理性 / MH/T 5078

### BG-4 日期合理性
- **检查什么**：施工日期是否在合理时间范围内
- **怎么查**：
  - 施工日期不在冬季施工期（12月~2月）但记录了冬季施工措施 → 矛盾
  - 施工日期为节假日但记录了正常施工 → 需确认
- **判断标准**：日期不合理 → 🔵 Best Practice 警告
- **规范依据**：L3 业务合理性

### BG-5 数值范围合理性
- **检查什么**：关键数值是否在规范允许范围内
- **怎么查**：
  - 桩径偏差 ≤ ±20mm（MH 5007）
  - 桩位偏差 ≤ 50mm（MH 5007）
  - 混凝土强度 ≥ 设计值
- **判断标准**：超范围 → 🔵 Best Practice 警告
- **规范依据**：各专业技术规范

## 五、检查清单执行顺序

```
1. DQ-1~DQ-4（数据质量检查，前置硬门槛）
   └─ 有 error → 停止，要求重新提取
   └─ 有 high → 标注，继续

2. IR-1~IR-15（铁律检查）
   └─ 有 ❌ → Fatal 级审核意见

3. LG-1~LG-10（逻辑一致性检查）
   └─ 有 ❌ → Sanity Check 级审核意见

4. BG-1~BG-5（业务合理性检查）
   └─ 有 ❌ → Best Practice 级审核意见

5. 汇总所有审核意见 → 生成审核日志 JSON
6. 套用报告模板 → 生成 HTML 审核报告
```

> **低智商模型适配要点**：每条检查项都是独立的"是/否"判断，不需要跨项推理。AI 按顺序执行 1→5，每项输出明确结论即可。
