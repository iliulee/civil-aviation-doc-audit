# 高频错误模式库

> 民航施工资料审核中**最常见、影响最大**的错误模式集合。
> 框架已搭好，**真实案例待你后续补充**——补充方式：直接在对应模式下追加"实际案例"段落。

## 一、格式类错误（频次：高）

### 1.1 签字不规范

| 错误模式 | 典型表现 | 严重度 | 依据条款 |
|---------|---------|--------|---------|
| 签字人未签字 | 表格内容已填但签字栏空白 | 中 | MH/T 5078.1 第8章 |
| 签字无日期 | 签字但未填写日期 | 中 | MH/T 5078.1 第8章 |
| 用印章代替签字 | 应签字处盖私章 | 中 | MH/T 5078.1 第8章 |
| 签字人非本人 | 字体明显不同、代签无授权 | 高 | MH/T 5078.1 第8章 + 铁律6 |
| 签字人无授权 | 监理签字人无授权书 | 中 | MH 5031 第3章 |

### 1.2 表格格式错误

| 错误模式 | 典型表现 | 严重度 |
|---------|---------|--------|
| 表格版本不一致 | 同类资料用不同版本表格 | 中 |
| 编号缺失/重复 | 资料编号漏号或重号 | 中 |
| 工程名称错误 | 与实际项目名称不一致 | 中 |
| 单位不规范 | 压实度写"96"未写"96%" | 低 |
| 数字保留位数不规范 | 千分位、百分位不统一 | 低 |

### 1.3 用词不规范

| 错误模式 | 典型表现 |
|---------|---------|
| 模糊用语 | "基本合格""大致符合""可能不行" |
| 口语化 | "差不多""可以了""没问题" |
| 描述与实际不符 | "未发生异常"但监理日志有异常记录 |

## 二、时效类错误（频次：高）

### 2.1 时间逻辑错误

| 错误模式 | 典型表现 | 严重度 |
|---------|---------|--------|
| 检验批日期早于材料报审日期 | 材料还没进场合格就用了 | 🔴 高 |
| 隐蔽工程验收日期晚于下道工序日期 | 已覆盖才验收 | 🔴 高 |
| 监理通知单晚于问题发生日期 | 整改后才下发 | 🟡 中 |
| 复工日期早于停工日期 | 时间倒签 | 🔴 高 |
| 28天强度试压日期过早 | 不足28天 | 🟡 中 |
| 沉降观测间断 | 关键期漏测 | 🟡 中 |
| 节假日无说明 | 节假日仍施工但无说明 | 🟢 低 |

### 2.2 阶段性资料缺失

| 错误模式 | 典型表现 |
|---------|---------|
| 开工报审缺失 | 已开工但无开工报审 |
| 阶段性验收缺失 | 跳过中间验收直接竣工 |
| 设计变更未闭环 | 变更已实施但无变更手续 |
| 暂停/复工手续缺失 | 停工后无正式手续 |

## 三、实体类错误（频次：中）

### 3.1 检验批数据异常

| 错误模式 | 典型表现 | 检查方法 |
|---------|---------|---------|
| 压实度异常 | 同一段落数据忽高忽低 | 查压实度数据 |
| 强度异常 | 试件强度低于设计值但无处理 | 查强度评定+处理记录 |
| 平整度超限 | 3m直尺超 5mm | 查检验批 |
| 厚度不足 | 钻孔取样厚度低于设计 | 查厚度检测 |
| 高程偏差大 | 与设计偏差超允许 | 查测量记录 |

### 3.2 检测报告问题

| 错误模式 | 典型表现 |
|---------|---------|
| 报告无资质 | 检测机构无相应资质 |
| 报告超期 | 检测报告超过资质有效期 |
| 检测项目不全 | 应检项目漏检 |
| 见证取样不规范 | 无见证记录或见证人非监理 |
| 检测结论模糊 | "基本符合""参考使用" |
| 不合格无处理 | 检测不合格但无复验/退货记录 |

## 四、管理类错误（频次：高）

### 4.1 人员管理问题

| 错误模式 | 典型表现 |
|---------|---------|
| 项目经理变更无手续 | 实际管理人员已变更但资料仍是原人 |
| 五大员不到岗 | 资料签字人不在岗 |
| 特种作业人员无证 | 电工、焊工等无操作证 |
| 监理人员未报审 | 监理调整未办理变更手续 |
| 执业印章缺失 | 设计变更、关键工序无执业印章 |

### 4.2 资质/报审问题

| 错误模式 | 典型表现 |
|---------|---------|
| 分包未报审 | 分包队伍未报监理审批 |
| 资质过期 | 检测/施工/监理资质过期未续 |
| 设备未报验 | 关键设备（如摊铺机、压路机）未报验 |
| 试验室未备案 | 项目试验室未在质监站备案 |

## 五、归档类错误（频次：高）

### 5.1 资料齐全性问题

| 错误模式 | 典型表现 | 严重度 |
|---------|---------|--------|
| 资料未与工程同步 | 工程已完工，资料未形成 | 🔴 高 |
| 资料"基本齐全" | 不达归档标准 | 🟡 中 |
| 缺少关键资料 | 无竣工图、无竣工验收文件 | 🔴 高 |
| 资料分散 | 各专业资料未统一管理 | 🟡 中 |
| 资料未分类组卷 | 杂乱堆放 | 🟡 中 |

### 5.2 资料真实性问题（铁律 6 重点）

| 错误模式 | 典型表现 |
|---------|---------|
| 时间倒签 | 资料日期与实际不符 |
| 代签字 | 不同时间签字笔迹雷同 |
| 数据雷同 | 多份资料数据完全相同（如不同点压实度均为 96.8%）|
| 影像资料缺失 | 关键工序无影像 |
| 描述与实际不符 | 资料描述与现场情况矛盾 |

### 案例 1：碎石桩施工记录数据造假嫌疑（大理机场改扩建）

**资料类型**：碎石桩施工记录（2016.4.20，桩号 Z420~Z415）
**错误类型**：数据真实性 / 五类问题并发
**错误描述**：
1. **竖直度交替循环**：6 根桩的竖直度仅 0.2 和 0.3 两个值交替出现（0.2→0.3→0.2→0.3→0.2→0.3），是典型手工编造特征，实际施工中竖直度不可能精确地只取两个值并交替循环
2. **桩长断崖下跌**：第 3→4 行实长从 13.7m 骤降至 9.0m（降幅 34%），且后续 4 根桩实长均远小于设计桩长 20m（分别为 13.7, 9.0, 9.0, 9.0, 8.5m），无持力层说明、无变更、无签证
3. **充盈系数涂改痕迹**：第 3 行记录充盈系数 1.37，但根据灌入量 3.48m³ / (π×0.3²×13.2m) 计算应为 0.93，偏差 0.44，远超 ±0.15 容差，疑似涂改
4. **灌入量突变**：第 2→3 行灌入量从 5.19m³ 骤降至 3.48m³（降幅 33%），与桩长下降同步但不匹配
5. **缺乏支撑文件**：所有 6 根桩均无持力层确认记录、无设计变更、无工程签证、无试验检测报告

**规范依据**：MH/T 5078.1-2024 第 8 章（资料真实性要求）、铁律 6（拒绝为伪造资料背书）
**发现方法**：data_quality_check.py 四类检测 + AI 视觉复核
- DQ-REPEAT-01：竖直度交替模式（自动化检测）
- DQ-JUMP-01：实长/灌入量突变（自动化检测）
- DQ-SELF-FC-01：充盈系数自洽失败（自动化检测）
- 人工复核：缺少持力层/变更/签证等支撑文件
**整改方法**：① 现场取芯验证桩长和竖直度；② 核实充盈系数原始记录，追溯涂改原因；③ 补办设计变更或补充持力层说明；④ 对资料签认人员启动调查
**审核启示**：数据质量问题往往是成群出现的——造假者会同时伪造多个参数，但各参数之间的工程逻辑关系（桩长 vs 灌入量、充盈系数 vs 理论值）难以自洽。**自洽校验是检测伪造的银弹。**

### 案例 2：Z418 桩长数据矛盾——同一桩号两份资料差异 4.19m（大理机场改扩建）

**资料类型**：碎石桩施工记录（DOC-A 未命名1.pdf vs DOC-B 扫描件.pdf）
**错误类型**：数据真实性 / 跨资料数据矛盾
**错误描述**：
1. **同一桩号数据矛盾**：Z418 在 DOC-A 中实长 13.2m，DOC-B 中实长 9.0m，差异 4.19m（32%）
2. **高程自洽失败**：DOC-B 中 Z418 桩底高程 2090.53m，桩顶高程 2103.72m，高程差 13.19m，但表内实长写 9.0m，差异 4.19m
3. **实长被改但高程没同步**：DOC-A 实长 13.2m ≈ 高程差 13.19m，说明原始数据是 13.2m 左右；DOC-B 实长被改为 9.0m，但桩底高程未同步修改
4. **修改意图推断**：将实长从 13.2m 改为 9.0m，使桩长从"遇岩石后停钻"的合理值变为"未达设计深度"的异常值，影响后续工程结算和验收

**规范依据**：MH/T 5078.1-2024 第 8 章（资料真实性要求）、铁律 6（拒绝为伪造资料背书）、铁律 12（高程自洽校验）
**发现方法**：
- AI 视觉逐格读取全列（包括桩底高程、桩顶高程）
- 逐根做高程自洽校验：实长 vs 桩顶高程−桩底高程
- 跨资料交叉对比：DOC-A vs DOC-B 同一桩号
**整改方法**：① 调取原始施工底稿核实 Z418 真实桩长；② 如无法调取原始底稿，现场取芯验证；③ 对 Z418 及相邻桩号的数据做全面复核；④ 追溯资料修改原因，启动责任调查
**审核启示**：造假者只改结果列（实长）不改计算列（高程），是检测造假的关键突破口。**数据自洽校验（铁律 12）必须作为所有表格审核的第一道硬门槛。**

### 案例 3：DOC-B 缺合计行——资料非原始记录的铁证（大理机场改扩建）

**资料类型**：碎石桩施工记录（DOC-B 扫描件.pdf，6页33根桩）
**错误类型**：资料真实性 / 资料来源判定
**错误描述**：
1. 6 页表格全部没有底部合计行（小计桩数、小计米数、小计灌入量）
2. 施工日志（DOC-C）中却有精确的合计值"33根，489.9m"
3. 合计值来源不明——不是从施工记录表上直接读出来的
4. 结合其他异常（桩号格式不统一、P15 跳号、签字模糊），高度怀疑 DOC-B 是事后誊抄件

**规范依据**：MH/T 5078.1-2024 第 6 章（资料及时性要求）、铁律 13（缺合计行=非原始记录）
**发现方法**：逐页检查表格底部结构，发现所有页签字栏直接跟在数据行下方，无合计行
**整改方法**：① 调取原始现场记录（原始底稿应有每页合计）；② 如原始记录已丢失，需补充说明资料来源和编制过程；③ 誊抄件需与原始记录逐页对账
**审核启示**：施工记录表格的"是否有合计行"是判断资料是否原始记录的最快方法。原始记录通常在每页底部有小计，最后一页有总计。**缺合计行的资料，数据真实性要打问号。**

### 案例 4：AI 提取不完整导致漏行漏列（铁律 16 核心案例）

**资料类型**：碎石桩施工记录扫描件（DOC-B 扫描件.pdf）
**错误类型**：提取完整性 / 审核流程缺陷
**错误描述**：
1. AI 初次提取只识别了 5 行数据，漏了第 6 根桩 Z415
2. AI 只读了"实长"列，没读"桩底高程"和"桩顶高程"列
3. 用户发现行数不对后，通过 AI 视觉重新提取才补全
4. 如果用户没有人工复核，行数不对 + 列不全的问题会直接进入后续审核，导致结论偏差

**规范依据**：铁律 16（提取-验证-重试循环）、铁律 2（OCR 必须人工复核）
**发现方法**：用户人工核对行数后发现
**整改方法**：① 提取后自动做行数校验；② 行数校验不通过自动触发 AI 视觉重新提取；③ 所有提取操作记录版本号，方便追溯
**审核启示**：**提取一次通过不可靠**。必须建立"提取→行数校验→通过/不通过→重试/停止"的闭环。行数校验是提取完整性的第一道硬门槛。

### 案例 5：审核结论置信度差异——同一份资料不同项可信度不同（铁律 18 核心案例）

**资料类型**：碎石桩施工记录（DOC-B 扫描件.pdf）
**错误类型**：审核结论表述 / 置信度分级
**错误描述**：
1. Z418 实长在 DOC-A 中 13.2m，DOC-B 中 9.0m，矛盾 → 置信度低（存疑）
2. 但 DOC-B 中 6 根桩的充盈系数都在 1.2~1.4 之间，且 DOC-A 中数据一致 → 置信度高（确定）
3. 如果审核报告统一写"资料不合格"，无法区分"实长存疑"和"充盈系数合格"的差异
4. 整改优先级也不同：实长存疑需现场验证，充盈系数合格无需整改

**规范依据**：铁律 18（审核结论置信度分级与表述规范）
**发现方法**：跨资料对比发现数据矛盾，单表自洽校验确定自洽通过项
**整改方法**：① 对每个不符合项逐项标注置信度；② 存疑项标注"建议现场验证"；③ 置信度高的项正常走整改流程
**审核启示**：**同一份资料中，不同项的置信度可以不同。** 审核报告不能一刀切说"合格"或"不合格"，必须逐项标注可信度，让整改方知道哪些需要现场验证、哪些可以直接整改。

## 七、错误严重度判定标准

| 严重度 | 判定标准 | 处理建议 |
|--------|---------|---------|
| 🔴 高 | 涉及伪造/重大违规/可能否决验收 | 必须立即整改+调查 |
| 🟡 中 | 资料不完整/不规范/可能影响验收 | 限期整改+复核 |
| 🟢 低 | 形式问题/轻微描述不当 | 通知整改+下次避免 |
